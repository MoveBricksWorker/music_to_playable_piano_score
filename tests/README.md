# 测试

这个目录里目前只有**一个**东西：[`regression.py`](regression.py)，一个回归闸门。
它不是单元测试，是**契约测试**——断言的是"这套管线当前做到什么程度"，
对应 README 里那张实测表。

```bash
python tests/regression.py --self-check     # 不需要 out/，新克隆的仓库就能跑
python tests/regression.py --verbose        # 对 out/ 的四首样例跑 28 条断言
```

## 它断言什么

| 断言 | 对应 README 的哪一句 |
|---|---|
| 单手跨度 ≤19 半音、同时音 ≤5 | "四首全部达标" |
| R1 = 0（三连音只以 3 或 6 个一组出现） | "R1 = 0 是这套管线目前最硬的一块" |
| 编排里的每个起音都能在成品 MusicXML 里找到，且音高集合一致 | "起音一个都没丢" |
| 谱面里有调号（`<fifths>`） | 调号解析的修复没有回退 |

## 它**故意不**断言什么

R2 / R3 / R4、临时记号数量、中段转调——这些**目前未达标**
（见 README「已知缺陷 & 路线图」）。写成断言会让 CI 常红，反而失去意义。
修好一条，就往 `regression.py` 里加一条。

## 为什么没有真正的单元测试

管线的每一层都依赖上层的真实产物（量化依赖真实的转谱输出，雕版依赖真实的量化输出），
造一套有意义的合成输入，成本比它挡住的风险高。目前性价比最高的防线是：

* `pipeline/check_shapes.py` 的**自证**（构造四种已知谱面，确认检查器会抓到该抓的）；
* 上面这个回归闸门（对真实样例断言硬指标）。

要在本地跑得更多，最省事的方式是拿整合包里的 `work/` 换一批输入再跑一遍闸门。

## CI

[`.github/workflows/verify.yml`](../.github/workflows/verify.yml) 会跑上面的闸门与
`tools/check_structure.py`，另外检查两件仓库卫生的事：

* `python/` `models/` `data/` `work/` **没有**被 git 跟踪（它们该走网盘）；
* 没有超过 50 MB 的跟踪文件（GitHub 会警告甚至拒绝推送）。
